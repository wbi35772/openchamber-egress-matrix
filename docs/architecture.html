01 · Overview

总览与能力

独立扩展，不依赖 sing-box，不维护外部 JSON 包或端口转换文件。

一个租约一个端口

租约 key 与本地端口一一对应，端口持久化在 state.ports。重启、重协调、增删其他租约都不改变已钉住的端口。

Fail-closed

消费方按 byKey[key] 取端口；key 不存在、线路未起、探测失败都直接失败。没有“回退直连”这个分支。

混合代理同端口

同一个监听同时识别 SOCKS5 握手、HTTP CONNECT 与 absolute-form 请求。浏览器、curl、扩展都只填一个地址。

三种上游来源

手动节点 URI、整池订阅、proxygate 槽位。来源只影响“这条线路指向哪”，不影响租约端口与契约结构。

端到端探测

探测不是问进程“你活着吗”，而是通过真实本地端口访问 probeUrl，把出口 IP 写回租约与契约文件。

零运行时依赖

只用 node:net、node:http、node:tls、node:crypto。没有 npm 安装步骤，装进扩展目录即运行。

数据流一句话：本地软件 → 混合监听（25001 / 251xx）→ 引擎按租约选择上游 → VLESS / Trojan over WS+TLS、SOCKS5 或 proxygate 槽位 → 目标站点。出口 IP 回写到 endpoints.json。

03 · Ports & Leases

端口与租约模型

端口是扩展之间的稳定契约，key 是账号与线路的身份。

key 命名约定

账号线路ibk/<alias>
订阅线路<prefix>/<node-slug>
槽位线路pg/<slot-id>
默认别名default

批量导入按节点名字生成 slug；重名自动追加 -2、-3，不覆盖已有 key。

三条不变量

  • 端口稳定：同一 key 的端口在重启后保持，除非你显式改口。
  • 冲突显式：端口被占就报错，不做“帮你换一个”的隐式行为。
  • 主口可切：primary 指向哪个租约，25001 就跟随哪个。
04 · Ingress

三种接入方式

单节点、订阅、proxygate 共用同一套租约与契约，不产生第二套节点池。

手动节点

面板「节点池」粘贴一条 URI，或调 POST /api/nodes。

  • vless:// WebSocket + TLS
  • trojan:// WebSocket + TLS
  • socks5:// 账号密码可选

稳定 适合固定账号出口。

订阅导入

面板「订阅」填 URL，支持明文或 base64 节点列表。

  • 按 URI 去重，重复同步只更新归属
  • 不覆盖手动节点
  • 可选 autoLease：导入即建租约
  • 可批量指定 key 前缀与起始端口

整池 适合机场/节点集。

proxygate 槽位

面板「上游」填 API 地址与 key，再「同步槽位」。

  • 槽位字段：slotId / port / country / exitIp / healthy
  • 槽位转成 SOCKS5 租约
  • 按国家过滤，支持轮换出口 IP

待验证 当前池子为空。

协议边界：只支持 VLESS / Trojan over WebSocket（含 TLS）与 SOCKS5。REALITY、gRPC、H2、Shadowsocks 暂不支持；本地只跑 TCP，不提供 UDP ASSOCIATE。

错误码

409 port_taken端口被其他租约或默认口占用
409 lease_key_exists租约 key 重复
400 node_missing租约引用的节点不存在
400 invalid_port端口不是 1–65535
502 subscription_*订阅超时 / HTML / 空列表 / 超 2 MB
401 unauthorized缺少或错误 Bearer token
08 · Runbook

运行手册

装、跑、测、排障。

安装到 OpenChamber

  1. 把仓库目录放进 ~/.config/openchamber/extensions/。
  2. 在 extensions.json 的 paths 登记该路径。
  3. 授予 service 能力（capabilityGrants）。
  4. 重启 OpenChamber，面板列表出现 Egress Matrix。
宿主只启动已登记的扩展；只复制文件不登记，面板不会出现。

开发运行

$env:OPENCHAMBER_SERVICE_PORT=25997
$env:EGRESS_MATRIX_DEV=1
node service/main.js

# 测试
node --test --test-force-exit

# 走默认口
curl.exe -x http://127.0.0.1:25001 https://api.ipify.org
curl.exe --socks5-hostname 127.0.0.1:25001 https://api.ipify.org

环境变量

OPENCHAMBER_SERVICE_PORT服务监听端口
OPENCHAMBER_SERVICE_TOKENBearer token
EGRESS_MATRIX_DEV1 = 允许无 token
EGRESS_MATRIX_DATA_DIR覆盖数据目录
EGRESS_MATRIX_PORT备用端口变量

验证一次出口

  1. 面板「出口线路」点「探测」，记下 exitIp。
  2. 打开 endpoints.json，确认 byKey 同 key 的 exitIp 一致。
  3. curl.exe -x http://127.0.0.1:25101 https://api.ipify.org 再核对。
  4. 停掉宿主服务，确认消费方失败而不是直连——这是 fail-closed 的反向验证。

10 · Limits

边界与排障

先看边界，再对症。

当前边界

  • 只跑 TCP；不支持 UDP ASSOCIATE。
  • 上游只支持 VLESS/Trojan over WS(+TLS) 与 SOCKS5。
  • 本地监听默认 127.0.0.1，不对局域网开放。
  • 订阅只接受明文或 base64 节点列表，HTML 登录页拒绝，上限 2 MB。
  • proxygate 槽位必须是可达的 SOCKS5；池空或边缘不可达时租约失败。
  • 没有自动故障切换：同一 key 的节点挂了就 fail-closed。

排障表

面板看不到扩展登记 extensions.json 并重启
NO_SERVICE授予 service 能力
HOST_TIMEOUT宿主忙或服务未起，查日志
端口冲突换端口或删旧租约（409）
exitIp 为空探测 URL 不可达或上游握手失败
订阅导入失败URL 需鉴权、返回 HTML 或超 2 MB
槽位同步失败API 地址 / key / 8090 可达性
11 · Roadmap

迭代路线

按“先稳定契约，再加弹性”的顺序。

P0 · proxygate 全链路实测 进行中

池子恢复后：槽位 → 租约端口 → 端到端出口 IP。当前只有单测，未连活实例。

P0 · 出口漂移告警 待做

记录首次 exitIp，探测发现变化时标记 drift；可选自动换线，避免账号出口悄悄变化。

P1 · 同国家节点池与故障切换 待做

租约绑定“国家 + 候选节点集合”，主节点失败时按顺序切换，端口保持不变。

P1 · SQLite 持久化 待做

用 node:sqlite 替换 state.json，支持并发写入、历史探测、租约审计与无损导入。

P1 · 批量导入与端口表 待做

CSV / JSON 批量定义 key → port → 节点，一次落稳几十个账号；面板提供可编辑端口矩阵。

P2 · 线路观测与限额 待做

每 lane 连接数、流量、失败率、最近错误；可配并发上限与速率上限。

P2 · 订阅定时同步与签名契约 待做

定时拉取订阅并增量建租约；endpoints.json 增加签名/校验，防止本机其他进程伪造。
